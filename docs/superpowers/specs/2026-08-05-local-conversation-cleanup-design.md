# 本地会话一键清理与安全回收空间

## 目标

允许用户清理全部桌面本地会话数据，并在用户选择重启后安全压缩数据库、归还磁盘空间。该操作不能删除或重置项目、模型配置、MCP、Skill、知识库、IM 会话或定时任务。

## 明确数据范围

`core-v2.db` 是共享数据库，不能整体删除。清理目标严格限定为绑定 `transport_id = 'desktop-chat'` 的对话，以及其关联的：消息、运行记录、交互、投递记录、线程计划、会话投影与事件日志。`context.db` 仅删除这些本地线程的上下文条目、压缩记录、状态和 head。

不匹配该 transport 的 IM 会话、`scheduled_tasks`、`scheduled_task_runs`、Agent profile 和所有其他数据库完全保留。`config.db` 只保存一个内部维护标记，不删除任何用户设置。

## 用户流程

在「设置 → 通用 → 本地数据与存储」新增“清理本地会话”危险操作。点击后弹出确认框，说明删除范围不可恢复；确认按钮使用“清理全部本地会话”。

清理前主进程拒绝存在运行中或排队中桌面本地 run 的请求，并提示用户先结束当前回答。清理开始后，设置页显示进行中状态，且新的桌面本地消息和 run 请求被主进程门禁拒绝。删除完成后，页面显示“会话已清理；重启应用可回收磁盘空间”，并提供“重启并回收空间”。

## 删除架构

主进程的 `LocalConversationCleanupService` 负责 single-flight 状态、预检查、门禁和 IPC。它停止现有单线程删除 worker，收集本地 conversation/thread 标识，随后 fork 一个独立 worker。worker 对固定数据库路径操作：按小批次删除 event log，按本地 conversation 删除其他级联数据，并在 context DB 中删除对应 thread 数据；遇到 `SQLITE_BUSY` 有限重试。它通过 IPC 回报进度，主线程不执行批量 SQL。

成功后服务清除对应的待删除队列项，解除本地会话门禁，并写入 `pending_local_conversation_compaction` 维护标记。失败时不写标记、解除门禁并向 UI 返回失败原因；已经提交的批次保持删除结果，重试只处理剩余本地会话。

## 重启压缩架构

“重启并回收空间”只设置重启请求；应用下一次启动在注册任何数据库 handler、网关、定时任务或运行时服务之前检查维护标记。若标记存在，启动一个独立维护 worker，对 `core-v2.db` 和 `context.db` 依次执行 WAL checkpoint 与 `VACUUM`，并等待其退出。

该时点没有主进程数据库连接或后台写入者，因此不会产生运行期锁竞争，也不会使 IM 或定时任务写入失败。两个数据库均成功后才移除维护标记。压缩失败会记录错误并继续正常启动；标记保留，用户可在设置页再次发起“重启并回收空间”。

## 错误与恢复

- 正在生成回答或队列中存在本地 run：拒绝清理，不中断用户会话。
- 重复点击：同一进程只允许一个清理任务；后续请求返回当前状态。
- worker 忙锁：有限退避重试；超限返回可读失败，不影响配置数据。
- 删除 worker 异常退出：门禁释放，状态变为失败，可重试。
- 压缩 worker 异常、磁盘空间不足或损坏：应用正常启动；维护标记保留并显示上次错误，不进行文件替换或删除。

## 测试

- worker 范围测试：仅删除 `desktop-chat` 对话及其 context，保留 IM、定时任务和 profile。
- service 测试：活动本地 run 拒绝、single-flight、worker 失败释放门禁、成功设置维护标记。
- 启动维护测试：仅在维护标记存在时运行；成功清标记；失败不中断启动。
- IPC 与渲染测试：确认操作、进行中禁用、重启回收入口以及错误展示。

## 非目标

本次不支持按单个会话选择清理、不清理 IM 历史、不估算每张表可释放的精确字节数，也不在运行中的应用进程内执行 `VACUUM`。
